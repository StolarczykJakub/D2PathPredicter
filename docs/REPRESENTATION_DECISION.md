The current V1 graph serves the fixed stairs-arrival comparison. Its entrance-relative coordinates and dependence on recognised rooms make it a poor fit for a first observation after an arbitrary teleport. The product needs to work locally on Windows 10 with visible imagery and authorized static data, predict NEXT and WP only with adequate evidence, and otherwise return `UNKNOWN`. A local feature vector can be built from the current image and can be evaluated without continuous exploration history. The quality of evidence and the latency of extracting it still need measurement. Keep the C# desktop implementation and the eventual p95 update target under 100 ms and peak working set under 100 MB as separate runtime checks. This offline pilot uses the existing Python standard-library workflow. ## Proposed minimal offline experiment

### 1. Same-frame repeatability using the frozen observations

Use the eight existing returns with original bytes preserved. Compare independent reviewers within the same frame and pass. Treat A and B as two regions or views of one development layout. The primary comparison can use RAW; repeat it with the V2 SEMANTIC marker and trace fields as a sensitivity check. The two passes in a given review share a session. The same-frame comparison is exploratory and the proposed criteria are prospective for this follow-up. [Frozen observations and limitations](ANNOTATION_RETEST_RESULTS.md)

- Start with player-relative glyph centres in native map axes and two observable hue groups. Preserve unknown appearance and measured radii. Compare a fixed-zoom marker-only score with a simple rotation-sensitive constellation of pairwise distances and angles. Require a stable nonzero baseline for any scale-normalized variant and retain fixed-zoom results alongside it. Avoid assigning a scale from a single close pair or forcing a rotation when several fits are possible. Use a minimum of two markers for a pairwise test and at least three non-collinear markers for a two-dimensional alignment claim.
- Compare marker-only against the same markers plus native wall occupancy and optional length-weighted orientation in a predeclared player-relative window. Use one fixed 120 px radius and a shared visibility mask declared before marks are scored. Mark any areas outside the crop, behind known masks or unavailable in a trace sample as unknown. Compare coverage in both directions, including the two-nearest-eight samples in full as a diagnostic. Use a deterministic synthetic split and merge of a fixed trace union to verify invariance independently of the real sample-selection difference.
- Use each annotation in turn as the query. Compute same-frame stability, A–B separation, matching margins and unresolved alignments. A and B may share layout motifs or visible cells. Any A–B match is a within-layout collision diagnostic. Include size-matched three-marker subsets of B so the marker count alone cannot distinguish it from A. Report both raw pixel and player-relative versions where relevant. Test every single-marker deletion, then contiguous crops that remove roughly 25% and 50% of the marks where the frame supports them. Keep counts, coverage and ties by mask. Simulated drops screen missing-data behaviour. Real image masking and teleport motion have separate gates.
- Keep all plausible alignments within the frozen tolerance. Repeated templates, identical scores, too few markers and out-of-corpus input produce unresolved results. Preserve candidates and set the direction output to `UNKNOWN` when plausible matches disagree or when support is insufficient. The diagnostic itself can stop at match sets without computing directions.

**Proposed screening gate.** At full visibility require all four directed same-frame queries per pass to retain the corresponding region as a compatible match. For the primary RAW comparison require zero false unique matches in controlled pairs and a better same-region score in both directions whenever the frozen registration verifies a distinct A–B comparison region. If no distinct region can be verified, report discrimination as inconclusive and keep A–B comparisons exploratory. In RAW require same-region compatibility for at least 80% of single-marker mask trials that still have at least two visible glyphs. Publish the fraction of trials eligible and the results for the two-mark cases separately. Require deterministic split/merge invariance on the unchanged synthetic wall union. Use at least 75% 3 px directional coverage in both directions on the preregistered common window as a provisional real wall-repeatability screen. Declare a wall result unavailable when comparable wall coverage cannot be established. Carry optional walls forward only if the wall screen passes and the walls remove at least one wrong-region candidate without removing a same-region candidate in a tested trial. Keep all wrong-region matches in the collision tally. If there are no discriminating trials, defer the wall choice. If full-view marker repeatability fails, treat the marker representation as unready and investigate the cause before adding layouts. If full views pass and masked views fail, retain only the observed visibility range and let poorer views abstain. Report same-region compatibility and false unique matches separately.

### 2. Small independent-layout screen, only if the first stage passes

Start with **two additional, deduplicated D2R layouts**, one for calibration and one untouched holdout. Keep the current layout in development. Use two identifiable regions per additional layout, one affected by clipping or ordinary obstruction if available, with two fresh RAW reviews per selected image. Include one extra image per layout with a changed player position in a region already annotated and overlapping visible geometry. Prefer an actual teleport frame where available. This requires at most six added images and twelve RAW reviews. Confirm from the corresponding recordings that the layouts are distinct, and keep every view or duplicate of a layout in one split. Record game build, mode, difficulty, zoom and visible extent. Use only player position and image geometry in matching. Region and layout IDs and reviewed overlap are available to the evaluator. The exact minimum grows only if a physical layout cannot be deduplicated or the selected views cannot be labelled reliably. [Benchmark split rules](../benchmarks/PROTOCOL.md#fixture-provenance-and-isolation)

Freeze thresholds using development and calibration before opening the holdout comparison. Measure within-region repeatability across reviewer and viewpoint changes, wrong-region ambiguity within a layout, and collisions or no-match outcomes between independently labelled layouts. Query held-out regions against the development set to test out-of-corpus behaviour. Use held-out view pairs only for evaluation of repeatability and overlap. Report collision counts with denominators and the number of correct unique matches, ambiguous sets and abstentions. A verified wrong unique region in the controlled comparisons rejects that matching rule as an identification claim. Preserve genuine collisions as compatible candidates. Advance to larger representation validation only if the correct region remains compatible for both fully visible holdout region pairs and the changed-player overlap case, with zero false unique results in the tested cases. One held-out layout is a falsification check with little power. Zero observed collisions in it gives no defensible collision-rate bound for D2R at large.

The proposed comparisons measure representation stability and discrimination. NEXT and WP utility calls for independently verified hidden-target labels, a disjoint multi-layout evaluation and a baseline comparison at matched coverage, as specified by the project benchmark. Keep WP anchor and discovery history under Role B’s separate capture protocol. [Offline benchmark](../benchmarks/PROTOCOL.md) · [WP capture protocol](WAYPOINT_CAPTURE_PROTOCOL.md)

**Estimated effort.** Allow roughly one focused half-day to one day for a small deterministic marker and wall diagnostic on frozen JSON, mask trials and a results table. Allow a further half-day to one day for selecting, deduplicating, reviewing and analysing the six independent-layout views if the first stage passes. Time and memory for automated image extraction or production matching are still unmeasured.
