# Research

Reviewed on 25 November 2026. All five named repositories were reachable, and at least one relevant source file from each was inspected. The descriptions below distinguish what the code exposes from the maintainers' reported validation. Phase 0 used source inspection. It produced no locally generated maps or D2R comparison measurements.

## Repository review

### emmericp/diablo2-maps

- **Language, license and maintenance.** C++ for extraction and seed tools, Go for the HTTP wrapper, and TypeScript/Vite for the renderer. MIT. The public `main` listing displayed two commits, with `0f65689` visible as the tip when checked. There is little public history from which to infer sustained maintenance. [Repository](https://github.com/emmericp/diablo2-maps), [CMake](https://github.com/emmericp/diablo2-maps/blob/main/seedgen/CMakeLists.txt), [renderer manifest](https://github.com/emmericp/diablo2-maps/blob/main/renderer/package.json), [visible tip](https://github.com/emmericp/diablo2-maps/commit/main)
- **Versions, capabilities and dependencies.** Classic 1.13c. The C++ map dumper uses the original 32-bit libraries and game data in a standalone process. The packaged stack adds Go, Node/Vite, and Wine for the Linux container. The Go lookup handler calls a separate C++ index reader. Rendering needs a candidate seed. Lookup derives candidates from a precomputed Tower Level 4 index. The maintainer's documented Normal-difficulty input is a detailed, manually reconstructed layout with room variants and grave states. [Classic loader](https://github.com/emmericp/diablo2-maps/blob/main/seedgen/src/d2loader.cpp), [lookup handler](https://github.com/emmericp/diablo2-maps/blob/main/mapserver/lookup.go), [deployment dependencies](https://github.com/emmericp/diablo2-maps/blob/main/Dockerfile), [observation protocol](https://github.com/emmericp/diablo2-maps#using-the-seed-finder)
- **D2R and reuse.** Direct D2R generation is unverified. The index reader can run without the game libraries given a compatible index. The standalone classic exporter has no running-game requirement but depends on original binaries. Use the room-orientation representation and the ordered-prefix lookup as design references. The project's full-space index estimate is about 40 GB, and its observation requirements are substantially richer than an entry automap. [Source tree](https://github.com/emmericp/diablo2-maps/tree/main/seedgen/src), [deployment notes](https://github.com/emmericp/diablo2-maps/blob/main/Dockerfile)

### jaenster/libd2

- **Language, license and maintenance.** Zig core with a C ABI and language bindings, including C#. MIT for the clean-room code, with an explicit exclusion for game-derived tables and other binary assets. The public history showed commits on 26 August 2026 and the releases page showed tagged releases. Treat the upstream version, managed binding, native binary and data manifest as one pinned set. [License](https://github.com/jaenster/libd2/blob/main/LICENSE), [history](https://github.com/jaenster/libd2/commits/main/), [releases](https://github.com/jaenster/libd2/releases)
- **Versions, capabilities and dependencies.** Targets classic 1.14d. DRLG takes a caller-supplied seed, difficulty and act. The reviewed C ABI and .NET wrapper expose room records, preset units and warps, adjacency, and optional subtile collision. `d2-drlg` depends on the sibling `formats`, `core` and `data` packages. The source embeds tables and some map assets. Confirm the exact data inventory and provenance for the chosen build. The reviewed build manifest declares Zig 0.17.0. The package README snapshot says 0.16, so use the chosen revision's manifest. A compatible published .NET binding carries a native binary and needs a matching ABI. [DRLG package](https://github.com/jaenster/libd2/tree/main/packages/drlg), [embedded inputs](https://github.com/jaenster/libd2/blob/main/packages/drlg/src/lib.zig#L49-L83), [build manifest](https://github.com/jaenster/libd2/blob/main/packages/drlg/build.zig.zon), [C ABI](https://github.com/jaenster/libd2/blob/main/packages/drlg/include/d2drlg.h), [.NET source](https://github.com/jaenster/libd2/blob/main/packages/dotnet/LibD2/Drlg/MapGenerator.cs)
- **D2R and reuse.** Best candidate for an offline classic reference export. The code exposes local generation without a game process or server. The maintainers report exact per-cell collision comparisons on classic Nightmare seeds, including two blind holdouts, with per-level CRC comparisons across all difficulties. These checks cover collision. Landmark coordinates, actual automap markings, and parity with any identified D2R build each need independent checks. [Validation evidence and limits](https://github.com/jaenster/libd2/blob/main/docs/VERIFICATION.md), [binding distribution](https://www.nuget.org/packages/LibD2)

### jcageman/d2mapapi

- **Language, license and maintenance.** C# / ASP.NET Core with a native C++ wrapper. The reviewed default branch did not show a repository license. The releases page shows v1.2 artifacts dated February 2022. Default-branch documentation describes newer version support and a newer toolchain. The latest activity date could not be confirmed. Reuse the response concepts without copying source whose license has yet to be established. [Repository tree and build notes](https://github.com/jcageman/d2mapapi), [release history](https://github.com/jcageman/d2mapapi/releases)
- **Versions, capabilities and dependencies.** Default branch documents classic 1.13c and 1.09d. The managed service constructs and caches a session keyed by map ID and difficulty. It returns an area's generated layout, collision and exits using the classic native libraries. The docs specify .NET 8, Visual Studio 2022 with C++ tools, and a classic installation. Wine/Docker is optional. The maintainer reports matching level layouts between versions in the comparable Normal setting. 1.09d ignores the difficulty argument. [Map service](https://github.com/jcageman/d2mapapi/blob/master/D2Map.Core/MapService.cs), [native wrapper](https://github.com/jcageman/d2mapapi/tree/master/D2Map.DllWrapper), [version notes](https://github.com/jcageman/d2mapapi#109-support)
- **D2R and reuse.** A supplied map seed is required. Generation runs without attaching to a live game, using classic DLLs and assets. The version-dependent implementation offers no verified D2R backend. The REST contract is a useful example of area bounds, collision arrays and labeled exits. It adds more dependencies than the first experiment needs.

### OpenDiablo2/OpenDiablo2

- **Language, license and maintenance.** Go, GPL-3.0, archived on 20 December 2021. The manifest targets Go 1.16 with dependencies including Ebiten. The full engine uses local classic Diablo II and Lord of Destruction MPQs. No supported retail patch matrix was established in the reviewed docs. [Repository and asset requirements](https://github.com/OpenDiablo2/OpenDiablo2), [Go manifest](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/go.mod)
- **Capabilities and reuse.** The DS1 and DT1 parsers and the engine's placement of map stamps are useful format references. Source shows a seed setter and an example map generator for the Act I overworld. Static preset parsing works with the relevant file bytes alone. Its randomized generation has a seed path, with no demonstrated reconstruction of retail Catacombs or Durance layouts. The independent engine does not require access to a running retail client. D2R parity is unverified. Consider the parsers as documentation. Direct code reuse would carry the project's GPL terms. [DS1 parser](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2common/d2fileformats/d2ds1/ds1.go), [DT1 parser](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2common/d2fileformats/d2dt1/dt1.go), [map engine](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2core/d2map/d2mapengine/engine.go), [generation package](https://github.com/OpenDiablo2/OpenDiablo2/tree/master/d2core/d2map/d2mapgen)

### lucas-gp/MapAssist

- **Language, license and maintenance.** C# Windows application, forked from `paradoxial/D2RAssist`. The README states GPLv3, and the reviewed `AreaData.cs` header allows GPLv3 or later. The fork has no published GitHub releases. Its latest fork commit date and supported D2R build range could not be confirmed. [Fork and license statement](https://github.com/lucas-gp/MapAssist), [source header](https://raw.githubusercontent.com/lucas-gp/MapAssist/main/Types/AreaData.cs), [fork releases](https://github.com/lucas-gp/MapAssist/releases)
- **Capabilities, dependencies and reuse.** `AreaData.cs` represents an area origin, collision grid, adjacent areas, adjacent exit positions and object positions. Its view-bound calculation derives wall boundaries from walkability for MapAssist's own rendering and uses `GameOverlay.Drawing`. The root contains a Windows C# project and a `MAServer.exe` map helper. The fork's project manifest and the helper's inputs, asset requirements, and version could not be established from the retrieved static files. The area model consumes a completed map. It establishes neither a source-verified, seed-driven standalone D2R generator nor a seedless generator. The representation can inform an independent schema. Standalone reuse of the map backend without game process access was not established. [Area model](https://raw.githubusercontent.com/lucas-gp/MapAssist/main/Types/AreaData.cs), [root tree](https://github.com/lucas-gp/MapAssist#readme)

## Static data and generation

The D2R field references below are from a mirrored Blizzard Data Guide and a community-maintained correction of that guide. The code references show how classic parsers or reconstructed classic engines handle the relevant structures. These sources have different patch coverage. [Guide provenance](https://github.com/eezstreet/d2rdoc/blob/master/about.html), [corrected guide](https://locbones.github.io/D2R_DataGuide/)

| File | Purpose and structure |
| --- | --- |
| DS1 | Versioned preset layout with dimensions, layers such as floors and walls, tile references and, in applicable versions, objects and substitution data. A DS1 describes a stamp or fixed layout. Procedural placement and connections between stamps come from the generator. [DS1 parser](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2common/d2fileformats/d2ds1/ds1.go) |
| DT1 | Tileset with tile identifiers, visual blocks and subtile flags. With the referenced DS1, it gives detailed terrain and collision features. Room-template footprints alone can suffice for a graph experiment. [DT1 parser](https://github.com/OpenDiablo2/OpenDiablo2/blob/master/d2common/d2fileformats/d2dt1/dt1.go) |
| `Levels.txt` | Area definitions including generator type, level type, dimensions by difficulty, and `Vis#` / `Warp#` links. These links specify possible destinations and the corresponding warp types. They do not encode the selected room-to-room graph or per-run stair coordinates. [Blizzard field definitions](https://raw.githubusercontent.com/eezstreet/d2rdoc/master/data/files/levels.js) |
| `LvlPrest.txt` | Preset definitions, DS1 file variants and a `Dt1Mask` selecting the relevant level-type tilesets. Presence of a target in one preset does not determine where that preset appears on a generated floor. [Data Guide](https://locbones.github.io/D2R_DataGuide/#lvlpresttxt), [classic loader](https://github.com/ThePhrozenKeep/D2MOO/blob/master/source/D2Common/src/DataTbls/LevelsTbls.cpp#L575-L622) |
| `LvlMaze.txt` | Maze room count parameters by difficulty, room dimensions and merge settings. The classic generator applies placement, overlap, connection, and special-room rules in code. [Data Guide](https://locbones.github.io/D2R_DataGuide/#lvlmazetxt), [classic maze code](https://github.com/ThePhrozenKeep/D2MOO/blob/master/source/D2Common/src/Drlg/DrlgMaze.cpp) |
| `LvlTypes.txt` | Level-type lookup for the DT1 tilesets combined with the preset mask. [Data Guide](https://locbones.github.io/D2R_DataGuide/#lvltypestxt) |
| `LvlWarp.txt` | Warp definitions including orientation, clickable area and relative arrival or walk-out offsets. Authored warp tiles in placed presets supply anchors, and `Levels.txt` plus the resolved adjacency supplies the destination. Verify which generator coordinate is the actual stair anchor since a room centre can also appear in export metadata. [Data Guide](https://locbones.github.io/D2R_DataGuide/#lvlwarptxt), [classic provider adjacency contract](https://github.com/jaenster/libd2/blob/main/packages/drlg/include/d2drlg.h#L145-L186) |
| `Automap.txt` | Maps level and terrain tile identifiers to displayed automap cells, with multiple cell choices for some entries. Object automap cells can also come from `Objects.txt`. The table gives rendering mappings for revealed features. [Data Guide on AutoMap](https://locbones.github.io/D2R_DataGuide/#automaptxt), [Data Guide on objects](https://locbones.github.io/D2R_DataGuide/#objectstxt) |

**Geometry and targets.** To model detailed terrain, join the preset's DS1 layers to its DT1 entries using level type and mask and apply the assembled room placements. A generated map also needs engine logic and, where used, substitution tables and object mappings. Intra-floor connectivity follows actual room placement and passable links. Inter-area connectivity uses level links and generated warp tiles. Catacombs Level 2 in the reconstructed classic code chooses orientation-specific next-floor and waypoint presets. Resolve NEXT by destination and an actual warp anchor. Resolve WP through the placed preset object and object identity. Treat a waypoint list or an area's waypoint setting as presence metadata. [Classic maze source](https://github.com/ThePhrozenKeep/D2MOO/blob/master/source/D2Common/src/Drlg/DrlgMaze.cpp#L630-L685), [Data Guide on Acts and waypoints](https://locbones.github.io/D2R_DataGuide/#actstxt), [provider preset contract](https://github.com/jaenster/libd2/blob/main/packages/drlg/include/d2drlg.h#L145-L186)

**Availability.** Public format descriptions and parser source are enough for research. The inputs for real references are versioned files from an authorized local installation or user-supplied observations. Classic installations organize assets in MPQs. D2R static-data workflows use Blizzard's CASC storage. Access, completeness, exact path layout and provenance for the chosen local build remain to be checked. Keep these files and captures outside version control. The listed source licenses cover code or documentation under their stated terms. [Classic asset requirements](https://github.com/OpenDiablo2/OpenDiablo2#open-diablo-2), [D2R data setup](https://eezstreet.github.io/d2rdoc/guides/getting-started.html), [CascLib](https://github.com/ladislav-zezula/CascLib)

**Determinism.** Authored tile identifiers, preset layers and table rules are fixed for a particular data version. A matching generator with the same seed, difficulty, act and map mode should reproduce the classic configuration within its documented coverage. Branches of the classic maze implementation use RNG for room selection and expansion, orientation-dependent special rooms and preset choices. D2R can change the generator, inputs or presentation by build or mode. Blizzard's legacy display toggle establishes continuity of presentation goals. Same-seed D2R layout agreement still requires measurements. [Classic maze source](https://github.com/ThePhrozenKeep/D2MOO/blob/master/source/D2Common/src/Drlg/DrlgMaze.cpp), [classic verification scope](https://github.com/jaenster/libd2/blob/main/docs/VERIFICATION.md), [Blizzard on the remaster](https://news.blizzard.com/en-us/article/23722094/bringing-the-original-diablo-ii-experience-to-console)

**Projection.** Template coordinates can be projected into approximate automap geometry by selecting the cells the automap displays and applying an isometric map transform. The sibling `libd2` render package has a classic tile-to-cell lookup that can serve as a reference without taking a rendering dependency. Collision outlines can supply a proxy during controlled tests. They omit display-specific distinctions such as certain outlined doors, omitted tiles, cell offsets, icon variants, reveal behavior and viewport clipping. Validate projection by overlaying corresponding landmarks on independently recorded imagery for a fixed display and zoom setting. [Classic cell lookup](https://github.com/jaenster/libd2/blob/main/packages/render/src/automap.zig), [AutoMap field guide](https://locbones.github.io/D2R_DataGuide/#automaptxt), [Blizzard's description of legacy rendering modes](https://news.blizzard.com/en-us/article/23788293/diablo-ii-resurrected-patch-2-4-ladder-now-live)

**Limits of inference.** When two layouts have the same visible cells under the accepted alignments, the observation can distinguish them only after conflicting evidence becomes visible. Possible differences include unseen branches, target locations, target-room orientation, and the underlying seed. Pixels also lose absolute world position unless there is a reliable origin, and they may omit collision, object identity and unrevealed portal destinations. Measure these ambiguities before budgeting time for a pixel extractor or a larger index.
