# Phase 1 recommendations

This is a proposal for the owner's approval. The first experiment targets **Catacombs Level 2, Normal, arriving from Level 1**, with NEXT to Level 3 and WP scored independently. It tests bearings while the landmark is hidden and uses a single recorded D2R build, game mode and automap setting. [Scope](../PROJECT_SCOPE.md) · [Verdict](FEASIBILITY_VERDICT.md)

## Smallest vertical slice

| Step | Work | Decision evidence |
| --- | --- | --- |
| 1. Establish the input path | Identify existing authorized footage or an independently labeled source with early automap frames, visible player position, progression and later verified landmarks. Record build, mode, difficulty, render mode, viewport, zoom, recording source and session provenance. Include multiple distinct layouts rather than repeated visits. | Independent reviewers can recognize the scenario, identify both landmarks or document missing truth, and align early positions to later labels on several different layouts. If the input path fails, stop the D2R experiment here. [F-01](FINDINGS.md#f-01) · [F-03](FINDINGS.md#f-03) |
| 2. Check observability before modeling | For an initial feasibility batch, use approximately 6–10 distinct layouts with two blinded annotations of the early frames. Mark visible features, uncertainty and player location. A separate pass labels the actual stair and destination and waypoint from later views. Use visible landmarks to map frames into a common scale and orientation with recorded residuals. Keep any evaluator alignment out of the features. Report usable fractions, feature agreement and cases with uncertain eligibility. | If independent readers cannot consistently describe the player, axes or limited visible geometry, revise the observation contract or stop. Document which features are legible and how often each target is still hidden. [F-04](FINDINGS.md#f-04) · [F-06](FINDINGS.md#f-06) |
| 3. Compare two cheap estimators | If the input check is promising, aim for 24–40 distinct layouts as a pilot acquisition target. Use a small offline table from manually transcribed geometry. Compare an unconditional development prior and the required entrance-axis prior with the same prior augmented by a few visible connector directions or branch counts. Use coarse fixed keys, minimum support, smoothing and fallback. Supply the same observed player frame to each method. Use grouped out-of-fold development predictions for exploratory diagnostics and preserve a separate untouched evaluation set for any product claim. | Per-target coverage, error, disagreements and direction reliability at arrival and one, two, three and five observable rooms, with three rooms primary. Report target discovery and usable geometry coverage. A handful of hand-authored synthetic cases verifies data flow and abstention. Pilot lift is directional evidence for planning and its uncertainty can remain large. [F-02](FINDINGS.md#f-02) · [F-05](FINDINGS.md#f-05) |
| 4. Extend only for a decision | If the pilot supports reliable inputs and plausible lift, pre-register an independent final benchmark sized from the observed variance. Freeze weighting, baselines, thresholds and grouping. Test a compact prefix table against the bounded scan only if the scan answers a material residual question. | Apply the D2R and performance gates per target. A large ambiguous low-support bucket or absent lift can end the case. A wide interval is inconclusive and must be reported that way. [Protocol](../../benchmarks/PROTOCOL.md) · [F-09](FINDINGS.md#f-09) |

Measure the earliest frame with sufficient **observable** evidence. If a room boundary is unclear, record it as uncountable and retain it in the observable coverage/attrition analysis. Keep the fixed three-room benchmark checkpoint and publish timing or feature-count diagnostics for cases that never reach three recognizable rooms before discovery. A target-blind route or predeclared time/checkpoint schedule helps avoid variation introduced by explorers following prior map knowledge.

## Specification and leakage checks

- Retain recording/game-instance IDs, known repeat relationships, version, true landmarks and eventually revealed geometry on the evaluator side. Freeze group manifests before model selection. Canonicalize complete geometry in the axes and equivalences allowed by the scenario and group near-identical known variants, same-map repeats and same geometry with different target labels. Audit cross-source overlap separately. If completeness prevents duplicate detection, report the limit and treat the result as pilot evidence. Preserve occurrence frequencies separately for probability estimation. [F-06](FINDINGS.md#f-06) · [F-07](FINDINGS.md#f-07)
- Record at each frame only visible geometry, the known/unknown mask and the visible player anchor. Use a fixed entrance context as part of the experiment configuration. Do not expose the seed, fixture ID, outcome, complete graph, authored template ID, later alignment or room boundary reconstructed from future frames. Predeclare what counts as target discovery for each landmark, including a recognizable icon, label, stair geometry or observed interaction. Mark uncertain timing or quality explicitly. [Protocol](../../benchmarks/PROTOCOL.md#observations) · [F-06](FINDINGS.md#f-06)
- Use the current player's position, common scale and canonical axes for all bearings. Use the two-way entrance axis when polarity cannot be observed and fall back to the unconditional prior when the axis is unknown. A small prior can retain training target offsets from the entrance and re-bin them from the observed player position. Keep target-level status distinct from match fit. Return `INSUFFICIENT_DATA` for unreadable/empty inputs and `UNKNOWN` for compatible contradictory or unsupported evidence. Record `NO_MATCH` as a diagnostic when a comparison explicitly rejects the reference pool. Distinguish known `NOT_APPLICABLE` from missing truth. A visible target is `DISCOVERED` and leaves predictive scoring. Report unknown and absent label mass explicitly. If directional probabilities condition on a target being present and labeled, report that denominator and include unresolved mass in the abstention policy. [F-05](FINDINGS.md#f-05) · [F-08](FINDINGS.md#f-08)
- Run two separate evaluations. A tiny **closed-set diagnostic** can inspect identity recovery when the true configuration exists in the pool. Count false exact fits under masking and misalignment. The **disjoint benchmark** measures only per-target direction/generalization. A compatible template from another layout is allowed and a reused full layout is leakage. Include a target-label permutation within comparable context and checkpoint strata to check for geometry-driven lift under a null. ## Measurement and decision

| Metric | Operational definition |
| --- | --- |
| Accuracy, false predictions and coverage | Use the same four dominant-axis sectors and declared tie rule for both methods. Coverage is predictions / eligible hidden targets. Accuracy is correct / predictions. False prediction rate is wrong / predictions, with wrong / eligible reported as an additional rate. Report correct / eligible and explicit abstention and missing-truth counts. Include first stable prediction checkpoint and feature count. |
| Bearing and position quality | Record wrapped absolute angular error in degrees when a direction angle is emitted. A sector-only output can be scored against its centre and labeled as a sector-centre error. Report median/p90 among predictions alongside coverage. For optional justified point estimates, use Euclidean error in canonical units, nominal room width and separate position coverage. A zero displacement has undefined bearing. |
| Ambiguity and out-of-distribution behavior | Count compatible distinct configurations and alignments for a scan, false unique fits in the closed set, and support/label entropy or sector disagreements for local bins. Report no-match, empty/unreadable and cross-alignment conflicts. Track how these measures change on the same still-hidden common cohort and on every checkpoint's eligible subset. |
| Confidence calibration | Use separate calibration groups for confidence thresholds or smoothing choices. Report per-target reliability bins with counts, mean probability and observed hit rate. Use multiclass Brier score for normalized distributions, with a declared treatment for unsupported/unknown mass and reporting denominator. Publish complete risk–coverage curves with fixed score tie handling and separate abstention. |
| Generalization and statistical evidence | Compare all methods on the same eligible observations and group-resampled splits. Compare coverage-matched prediction rankings at predeclared operating points, report how much the predicted subsets overlap, and show an additional paired comparison on mutually predicted observations. Bootstrap whole map groups using the fixed rank/tie policy. Estimate class imbalance and uncertainty in both absolute performance and lift. |
| Runtime | If an artifact is produced after approval, measure cold parse/build time, warm feature-to-prediction p50/p95 and worst case, input bytes, peak working set and hardware/runtime details. Include installation and index choices in the report. The current goals are p95 below 100 ms and peak working set below 100 MB. Measure the below-2%-CPU goal only in a later approved end-to-end test on target hardware. |

The proposed product gate is **at least 70% correct among predicted four-sector bearings and at least 60% coverage by the three-room checkpoint** for each target. Require at least **5 percentage points of observed lift** over the entrance prior at matched coverage and a paired 95% interval for the lift above zero. Apply frozen thresholds on the final groups. Report negative results and acquisition/eligibility attrition. If annotation or coverage fails, identify which stage prevented a decision. If sufficiently precise held-out results show the geometry adds little and a validated simple orientation rule alone provides useful coverage and accuracy, consider a rule-only pivot with owner approval. A one-target pass requires a scope decision. [Original gates](../FEASIBILITY.md#go-and-no-go-criteria)

For planning only, when two classifiers predict on the same paired cases, define `d` as the mean difference in correctness and `q` as their disagreement rate in correctness. The variance per pair is `q - d²`. With `d = .05` and `q = .20`, `1.96 × sqrt((.20 - .05²) / 150)` gives an illustrative half-width of 7.1 percentage points even with 150 paired scored cases. The normal planning approximation `(1.96 + .84)² × (.20 - .05²) / .05²` gives about 620 scored pairs for 80% power against zero under those assumptions. This does not plan power to clear a 5-point observed-effect gate and does not model differing predicted subsets. Use pilot-derived group resampling and observed eligible fraction to choose the actual acquisition target. [F-09](FINDINGS.md#f-09)

## Edge-case validation

Severity describes the damage if misleading behavior reaches evaluation or a later user-facing system. Test context transitions in a later observer if the fixed-scenario offline input cannot represent them.

| Case | Expected behavior and potential failure | Severity | Validation |
| --- | --- | --- | --- |
| Multiple matching fragments or identical geometry with different target locations | Retain distinct target outcomes, report ambiguity and abstain only where directional support is insufficient. Early tie-breaking can produce false certainty. | P1 | Same visible prefix, different hidden directions for both targets; a second case with agreement for NEXT only. |
| Symmetric rooms, rotations and mirrors | Preserve plausible axes, aggregate alignment weight once per map and transform player and target together. Unwarranted mirroring or equal votes per transform can swap quadrants. | P1 | Symmetric entrance under 180° rotation and left/right asymmetric variants. Verify reflection only where independently justified. |
| Different scale, resolution, pan or viewport | Use registered units with explicit uncertainty. Unmatched settings should yield low evidence. Fixed pixel distances can misalign doors or the player. | P1 | Repeat the same observations at known zoom and resolution changes and measure residuals and sector agreement. |
| Minimap/fullscreen modes and classic/remastered graphics | Gate on the validated display mode or demonstrate robust mapping across modes. Mode changes can present a stale transform and different reveal masks. | P1 | Paired screenshots across modes, including legacy and remastered presentation. Compare features, clipping and anchor error independently. |
| Partly visible or clipped room | Treat uncertain edges as unknown. A cropped connector can otherwise reject valid arrangements or inflate room counts. | P1 | Crop the same connector just inside/outside the mask and compare known-absent with unknown cases. |
| Automap transparency and background interference | Report uncertain features and abstain when the player or reliable geometry is unreadable. Game scenery can introduce false connectors or hide lines. | P1 | Same room under varied brightness/alpha and backgrounds. Measure missed and spurious features with independent annotation. |
| Teleportation and disconnected fragments | Avoid inventing links, preserve separately registered observations or drop uncertain fragments. A false bridge can create a nonexistent path. | P1 | Revisit disjoint frames with a gap and one known positional anchor. Check that hidden topology never enters input. |
| Large movement, wrong player position or boundary/zero vectors | Recompute the bearing from the current anchor. Stale or uncertain anchors should reduce support or trigger abstention. | P1 | Shift an otherwise identical view, inject position error across a diagonal, and test zero displacement and missing position. |
| New area, new game or different difficulty | Invalidate state and require supported context before giving a bearing. Matching entrance pixels can hide an area or session change. | P1 | Replay identical fragments separated by explicit area, game and difficulty transitions. |
| Area without WP | Return `NOT_APPLICABLE` only when context independently establishes absence. An unavailable label yields UNKNOWN. | P1 | Test an authorized known no-WP fixture and one missing-label case with the same visible geometry. |
| Multiple exits or optional side areas | Score the designated destination and avoid treating arbitrary exits as NEXT. | P1 | Include Level 1 stairs, Level 3 stairs, and an optional branch in a contract fixture with a known destination. |
| Incorrect area identification or unsupported generation rules | Unknown context yields UNKNOWN, with no reuse of previous estimates. Over-generalized priors can give plausible wrong directions. | P1 | Present a different floor or generation family with the same entrance geometry and unknown context. |
| Previously unseen layouts and no matching candidates | Preserve calibrated predictions if a backed-off prior is supported. Otherwise abstain. A forced nearest-map fit can misidentify both targets. | P1 | Disjoint complete layouts with common, rare and unmatched prefixes. Report false confident predictions and no-match. |
| Conflicting observations or malformed/empty input | Report the invalid state or abstain. Suppress stale results until observations are consistent. | P1 | Supply present/absent conflicts at a known boundary, impossible coordinates and an empty mask. |
| Target discovered earlier than expected | Exclude the target from predictive scoring at discovery. A late frame can inflate both accuracy and reported coverage. | P1 | Compare icon, label and anchor exposure, including a clipped icon and a player arriving via waypoint as an ineligible context. |

## Component and scope decisions

| Proposed component | Purpose and minimum needed now | Place and timing |
| --- | --- | --- |
| Provider adapters, DS1/DT1 and tile-to-automap projection | Can generate diagnostic classic references and eventually explain feature loss. Direct D2R annotation answers the first geometry question sooner. | Optional research utility after the input pilot. Verify classic anchors and provenance if used. |
| General synthetic generator and reveal simulator | Can exercise controlled edge cases and noise. A handful of explicit masks and replayed annotated checkpoints serves the first experiment. A large invented family adds work and can encode shortcuts. | Hand-authored contract cases in offline research first. Add a simulator only for a specific controlled question. |
| Geometry normalization and registration | Required for comparable bearings and uncertainty. Start with fixed axes and manually checked landmarks, including a truth-only transform if needed. | Offline annotation and evaluation initially. Implement pixel extraction after real geometry has shown value. |
| Orientation prior and small local feature table | Establish a cheap comparison and estimate whether geometry adds signal. A few categorical features and counts are enough to start. | Offline analysis initially. Suitable for a minimal runtime if validated. |
| Whole-map scan, fingerprint index and general graph search | A bounded scan can test richer features, and an index can later reduce cost. They have little purpose before local feature signal or a cost limit is measured. Unanchored graph search and a full seed index add substantial complexity. | Defer scan and index to measured needs. Keep general graph and seed inversion out of the first scope. |
| Evidential abstention and reporting | Required to avoid misleading bearings and audit coverage. Reuse a fixed table and simple report. | Shared evaluation contract with a compact eventual runtime status. |
| Coordinate estimate and routing | Optional point estimates need validated anchors and stable local regions. Routing needs passable connectivity and user-value evidence. | Postpone point estimates. Routing is outside the first bearing experiment. |
| Screen capture, overlay, session cache and C# desktop | Would support a deployed assistant. The first test uses recorded annotated data and a simple offline analysis with the installed Python if code is approved. | Defer desktop integration and benchmark it on a supported Windows host. |
| Database, service, AI model and general infrastructure | Local tabular data and ordinary counts satisfy the pilot. | Exclude from the proposed slice. |
