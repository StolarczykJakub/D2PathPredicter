# Risk register

Probability reflects the current evidence in the scoped scenario. “Present” means the prerequisite gap already exists. High, medium and unknown are qualitative judgments because the project has no measured D2R rates. Impact refers to the decision or intended application.

| Risk | Probability | Impact | Evidence | Mitigation | Validation experiment |
| --- | --- | --- | --- | --- | --- |
| R-01 · Independent D2R dataset cannot be obtained in the required context | Present in workspace. External availability unknown. | Critical · Product gate blocked | [F-01](FINDINGS.md#f-01) | Confirm an authorized source before implementation. Restrict scope to a recorded build/mode and Normal stairs arrival. | Inspect paired early/later clips from several distinct layouts and independently label both targets. |
| R-02 · Early observations carry little target information | Medium · Classic constraints give reason to test, while real rates are unknown. | Critical · Core utility may fail | [F-02](FINDINGS.md#f-02) · [F-05](FINDINGS.md#f-05) | Compare a small number of visible features with an entrance prior, with calibrated abstention. | Measure group-level unseen-layout lift and label disagreement by checkpoint; test the level of useful coverage before discovery. |
| R-03 · Landmark labels are wrong or misregistered | High if automatic bridge-centre export is used. Direct-label risk unmeasured. | High · Invalid targets and scores | [F-03](FINDINGS.md#f-03) | Verify destination and placed landmark independently, and record position uncertainty. | Compare target markers and anchors in paired imagery, including a stair whose anchor and room centre fall on different sides of a sector boundary. |
| R-04 · Real imagery removes the features that make the geometry test work | Medium to high · Sparse display and mode changes are verified. | High · Synthetic/classic result may not transfer | [F-04](FINDINGS.md#f-04) | Use blinded early real-image annotations first. Keep the first view fixed and use explicit unknown masks. | Double-annotate a pilot subset, compare feature agreement and coverage, and test held-out registration residuals before implementing extraction. |
| R-05 · Hidden metadata, future geometry or duplicate layouts leak into evaluation | Medium · Protocol has split safeguards but no validator exists. | High · False pass on unseen maps | [F-06](FINDINGS.md#f-06) | Freeze full-geometry groups and early visible data before final scoring. | Audit group overlap, redact future frames, perturb truth labels without changing model input, and check target-permutation controls. |
| R-06 · Sparse or biased reference support produces confident wrong answers | Medium | High · Misleading runtime bearings | [F-05](FINDINGS.md#f-05) · [F-07](FINDINGS.md#f-07) · [F-08](FINDINGS.md#f-08) | Measure support, back off or abstain, retain alignments and test weighted priors. | Replay repeated and shifted layout frequencies, symmetric completions, out-of-corpus layouts and noisy position estimates. Report false predictions and calibration. |
| R-07 · Sample size and discovery attrition make modest lift inconclusive | High at pilot scale for effects near the threshold. Exact power unknown. | High · Cannot make a reliable utility decision | [F-06](FINDINGS.md#f-06) · [F-09](FINDINGS.md#f-09) | Pre-register sample and analysis from a pilot; report precision, eligibility and fixed-cohort changes. | Resample independent groups using observed discordance and coverage, and verify the interval has useful width for each target. |
| R-08 · Unsupported context reuses stale or inapplicable advice | Medium if future state persists without a session boundary | High · Wrong floor, landmark or game | [F-10](FINDINGS.md#f-10) | Gate supported context, clear state on changes and distinguish unsupported from absent. | Replay identical initial fragments across different sessions/orientations and check previous predictions are invalidated. |
| R-09 · Scan or full-map corpus violates latency/RAM budgets | Medium for a small slice, high for large scans under the stated model | High · Resource goal missed | [F-11](FINDINGS.md#f-11) | Start with a compact conditional prior. Add a bounded index only when a measured gain requires it. | Measure warm p50/p95/worst, cold load, peak working set and quality versus reference size using common splits. |
| R-10 · Classic provider build or asset grant cannot be reproduced | Medium | Medium for an optional export. High if made mandatory. | [F-12](FINDINGS.md#f-12) | Keep provider optional. Pin toolchain, ABI, build and input provenance. | Rebuild or run on a supported host with authorized inputs, then verify repeatable classic output and independently labeled anchors. |
| R-11 · Current host cannot support intended C# delivery | Present as a documented support mismatch | Medium now. High at desktop delivery. | [F-13](FINDINGS.md#f-13) | Use the existing interpreter for offline research and settle production host/OS support before deployment. | Run release C# on the supported target Windows edition and repeat resource measurements. |
| R-12 · Better bearings do little to shorten exploration | Unknown | Medium · Product value remains uncertain after an offline pass | [F-14](FINDINGS.md#f-14) | Describe bearings as estimates and compare a lightweight rule in a later offline route replay. | Measure branch decisions and discovery distance/time under matched start states and route policies. |
