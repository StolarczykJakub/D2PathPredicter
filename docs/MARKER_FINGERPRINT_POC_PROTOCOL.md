# Phase 1.6.2 Stage 1 experiment protocol

Frozen on 2026-11-26 before running marker comparisons. The owner approved the existing-observation screen in the [representation decision](REPRESENTATION_DECISION.md#1-same-frame-repeatability-using-the-frozen-observations). Apply that document's gates with the operational choices below. Use the four frozen V2 packet pairs only. RAW is primary and SEMANTIC is a sensitivity check in a separate run.

## Matcher

- A stores observed glyph centres in native axes relative to the observed player. It stores each marker radius and the player radius separately. Classify text containing yellow as yellow, purple or magenta as one hue group, and any other appearance as unknown. Unknown is compatible with either group. Exclude unresolved centres. Sort by geometry and hue for reproducible enumeration. Ignore row IDs and enumeration order as evidence.
- B keeps the same markers and directed inter-marker vectors. A vector encodes length and clockwise angle from map-up. Compare vectors by Euclidean difference in native axes, which incorporates both length and angle. Only translation is allowed, at the recorded zoom. No rescaling, reflections or rotations are used. The algorithm enumerates distinct full correspondences and records the mean reference-minus-query offset for each. Keep each feasible correspondence even when a competitor has a better score. Label the offset as a hypothesis, without claiming a unique transform. A 2D alignment claim requires a triple on both sides whose shortest altitude exceeds the sum of the three marking radii.
- Require at least two visible markers on both sides. Match every marker on the smaller side one-to-one to a subset of the larger side. Equal-sized sets require a bijection. Extra marks outside the tested evidence are unscored. A point requires a compatible hue and a distance at most the smaller of 8 px and the sum of both marker and player radii. B applies the same 8 px cap to every directed vector between corresponding points, with uncertainty equal to the four endpoint marking radii. Player uncertainty cancels in those vectors. A two-marker B match is pairwise-compatible and its 2D alignment is unresolved. Use the arithmetic mean of residual divided by tolerance as the correspondence score, with zero for an exact residual at zero tolerance. Lower is closer. Use the minimum feasible score to report similarity, retain all assignments and report hypothesis counts. An incompatible pair has no score. A finite margin is cross-frame score minus same-frame score when both exist. A compatible same-frame pair outranks an incompatible cross-frame pair.
- C uses A and the union of the sampled wall centrelines rasterized in native pixels. Use a 120 px player-relative disk, screen bounds and the two frozen release rectangles, intersecting the known masks in both coordinate systems. A contiguous query crop also clips the comparison window at its declared relative edge on both sides. Marker-only omissions and arbitrary three-point subsets leave independent wall evidence unchanged. Compare only recorded line points. For each side compute the fraction within 3 px of any point on the other side inside the mask. Treat two nonempty sampled unions as available for this positive-coverage diagnostic. Treat all areas with no trace evidence as unknown, including omissions due to the cap. Walls support a candidate if both fractions are at least 75%. When at least two A candidates survive and at least one has wall support, report a provisional wall-supported shortlist while retaining the original compatible candidates. Measure the effect of that shortlist. A single A candidate is retained on its own. Full-view wall repeatability requires both directions of each RAW same-frame pair to clear 75%. Include the entire sampled union in a separate descriptive audit. Skip optional orientation histograms. Require exact raster-union equality on synthetic unchanged horizontal, vertical, diagonal and gapped segments under splitting and endpoint reversal.

## Trials and labels

- Each of the four observations in a pass queries the opposite-slot annotation on each frame. One reference is the independently reviewed same frame and the other is the separately reviewed other frame. Run full views first. For the size control exhaust all three-marker subsets of B on the query side when B is the query and on the reference side when A is the query. Use geometry-sorted combination enumeration. The independently reviewed same-frame reference remains full. Score these trials individually and keep same-frame references distinct from their query observation.
- Remove each query marker in turn. Separately make four contiguous axis-aligned query crops for each of 25% and 50% removal, keeping the low and high ends of each axis. Target the nearest integer removal count with half rounded up. Use the retained boundary marker to set the half-plane and keep all points on the boundary, including ties. Reference markers remain full. Count every attempted crop and deletion. Report the actual removed counts, eligible and ineligible trials, and all two-marker outcomes. None of these masks change the player coordinate.
- Before scoring, verify the frozen V2 hashes, pinned V1 files and registration screen. In the evaluator only, compare against the existing pixel-recheck fixed-zoom translations for Stage 0 and Stage 3. Use the frozen registration screen of three anchors, a 64 px baseline, an off-axis holdout over 6 px, scale in [0.97, 1.03], absolute rotation at most 2°, and fitted and held-out residuals at most 6 px. For physical-label purposes, mark cross-frame presentations as overlapping when at least one known-hue centre agrees within 8 px after registration. Mark them distinct only when the registered centre bounding boxes, expanded per marker by its radius plus 6 px per frame for transfer, are disjoint. Otherwise mark the relation unresolved. Apply this rule to each tested feature subset. A shared landmark in one comparison does not label every subset as overlapping, and a distinct descriptor window does not establish a distinct layout. Registration, physical labels, packet IDs and region IDs are evaluator-only. Use exclusively geometry, uncertainty, hue and mask support in scores.
- A compatible cross-frame candidate is counted and broken down by physical relation. Use the wrong-region collision and false-unique denominators only on eligible, verified-distinct comparisons. A verified-distinct candidate alone is a false unique only when an alignment can be resolved. Report separately when it is the sole compatible candidate but has unresolved alignment evidence. An overlap or unresolved relation can produce an unverified cross-only result. More than one compatible reference or correspondence is ambiguous. A sole B correspondence without a supported 2D alignment is unresolved. No eligible correspondence yields no match. Fewer than two markers means ineligible. Report resolved unique same-frame outcomes separately from correct-region compatibility.

## Gates and decision

- For each representation require four of four full-view same-frame compatibilities in each pass. In RAW require zero false unique results where a distinct reference was verified, strictly better same-frame scores or compatibility in both directions with verified distinct full regions, and at least 80% same-frame compatibility among eligible single-deletion trials. If full views overlap or cannot be verified as distinct, the full-view discrimination gate is NOT EVALUABLE. Apply the same strict score check separately on verified distinct size-matched subsets, and report partial-mask comparisons descriptively beyond the deletion gate. Compatibility of two-point B evidence counts for the deletion gate while its alignment remains unresolved.
- Carry walls forward only if the synthetic invariance and both-frame RAW wall-repeatability gates pass and the shortlist excludes at least one verified wrong-region candidate while retaining every compatible same-frame candidate. Report which comparisons support this finding. A marker baseline with no verified wrong candidate gives no demonstrated incremental discrimination.
- Prefer A if marker repeatability, eligible deletions and the controlled distinct comparisons support it. Choose B only when it resolves a measured A limitation and satisfies the same criteria. Choose C only with the documented incremental wall benefit. Use D for a specific correctable representation failure and E when results cannot support a next representation action. Any recommendation to advance is a further small falsification screen on independent layouts, pending owner approval.

## Cost and reproduction

Use Python's standard library. Time execution-only construction and full-view pair operations after 10 warm-up repetitions and 100 measured repetitions per RAW case. Report p50 and p95 using inclusive quantiles. Measure compact JSON descriptor size and Python traced peak allocations on the same operations in a separate pass. Report trial and candidate-pair counts and worst-case algorithmic bounds. No runtime image parsing or target scoring is included.
