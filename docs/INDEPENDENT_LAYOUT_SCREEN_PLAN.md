## Dataset and labels

Keep `mapa-07` wholly in development. Assign one new recording layout to calibration and one to holdout. Each has two physically distinct regions, three source frames and two independent reviews per frame. Record the existing capture context, frame PTS, exact source bytes, visual deduplication evidence, non-glyph registration points, and split and packet aliases in the private owner manifest. This is a D2R representation screen on the owner-reported Normal Catacombs Level 2 build and capture configuration. The three layouts form one development, one calibration and one holdout group. There are no static reference providers or target labels in this experiment.

Use the same 448×352 source window in every 1920×1080 image, with native bounds `736 ≤ x < 1184` and `364 ≤ y < 716`. Black padding keeps the native origin and hides UI, chat and the rest of the automap. The window fixes the spatial support for region labels. Scene effects, objects and actual rendering limits inside it are separate from the imposed boundary. For the development comparison, derive a view filtered to the same native window from the frozen RAW originals and keep the originals intact. A glyph belongs to the window when its centre is inside it. The extent records only its visible span.

The annotation protocol `marker-raw-v1` is a derivative of the V2 RAW contract. It retains player, markers, extents, radii, timing, search completeness and notes. The `walls` and `search_complete.walls` keys are intentionally absent from the schema. The measurement rules for a visible player, glyph centre and visible span remain those in the V2 guide. Both reviewers receive the same image bytes in separate packets. Each reviewer opens a fresh session for exactly one packet. [Packet guide](INDEPENDENT_LAYOUT_ANNOTATOR_GUIDE.md) · [V2 protocol](ANNOTATION_PROTOCOL_V2.md)

Registration uses native-pixel manual picks on corresponding **wall corners, bend points and junctions** in a source image and its same-recording late reference. Fit the longest anchor pair and validate the remaining points. Retain the existing 64 px minimum baseline, off-axis distance over 6 px, scale range 0.97–1.03, rotation magnitude at most 2°, and fitted and held-out residuals at most 6 px. Use translation at fixed zoom, with a conservative 6 px transfer allowance per image for region labels. Registered region-2 windows must be disjoint from both region-1 windows even after the transfer allowances. The region-1 pair also requires visible shared wall structure inside the overlap and verified player movement beyond the summed error budget. These coordinates, visual labels and the private mapping are evaluator-only. [Registration rules](REGISTRATION_VALIDATION.md#acceptance-rule-before-scoring)

## Before accessing holdout returns

1. Preserve original annotation bytes by packet ID and record SHA-256, reviewer identifier, handoff and receipt dates, and deviations. Validate packet, frame, dimensions, schema, unique glyph IDs, status/evidence consistency, bounds, radii, elapsed time, Boolean flags and notes. Keep invalid or partially usable returns intact. Keep the holdout returns sealed from calibration and analysis until the lock below exists. The evaluator may prepare holdout geometry labels without reading or scoring holdout annotations.
2. Use only development and calibration for candidate thresholds. Start with the existing fixed-axis, fixed-zoom translation model and hue grouping. A uses player offsets with both player and glyph radii. B uses directed point-pair vectors with glyph radii and a non-collinear triangle for a resolved 2D alignment. Keep both the smaller-set one-to-one support rule and all feasible alternatives. Use the Stage 1 lower-is-closer mean normalized residual. Allow an unknown hue as in Stage 1. Holdout IDs, registration, physical locations and labels stay outside match inputs. In B, known native glyph coordinates suffice if the player is unresolved because pair vectors are translation invariant. A requires an observed player. Never supply an evaluator player location to fill that field.
3. For each representation, compare predetermined caps of **4, 6 and 8 px**, using the smaller of the cap and the summed marking radii. Reject caps with a verified false unique calibration result. Among the remaining caps, choose the one with the greatest same-frame and moved-view compatible count on the complete, eligible calibration controls, counting each directed reviewer pair once. Break ties by fewer verified wrong-region compatible candidates across the same within-calibration and calibration-versus-development comparisons, then by the smaller cap. Publish each candidate's results and denominators. If caps fail to support required calibration pairs or the sample is insufficient, record the blocker and stop before opening holdout returns. Stage 1 code and its historical 8 px configuration remain frozen.
4. Before holdout, freeze the chosen caps, the development and calibration input hashes, holdout packet manifest and label hashes, the candidate roster and eligibility rules, and the exact bounded evaluator code and test hashes. Use an immutable calibration lock and record the holdout opening time. Compare holdout once with the locked configuration. Changes after opening require a newly reserved holdout before a confirmatory claim.

## Comparisons and eligibility

| Comparison | Query and candidate roster | Evidence |
| --- | --- | --- |
| Repeatability | Query both independent reviews of each frame against the other review of that frame and both reviews of the physically distinct region. A region-2 query uses both primary region-1 reviews as distinct controls. No self matches. | Same-frame compatibility in both directions and verified wrong-region candidates. |
| Changed player | Query both reviews of the primary and moved region-1 frames against both independent reviews of the opposite viewpoint and both reviews of region 2. Exclude the same-frame reference in this comparison. | Same-region compatibility under measured movement, with all four reviewer pairings in both directions. Report any genuine partial visibility and the imposed border separately. |
| Cross-layout and out-of-corpus | Query each holdout review against only the four windowed `mapa-07` development RAW observations. Report calibration-versus-development under its own denominator. | Every compatible candidate is a cross-layout local fingerprint collision. An empty candidate set is a valid out-of-corpus outcome. |

Eligibility requires a valid return, complete search of its supplied visible window and enough observed markers to compare. Preserve incomplete searches and time-limited partial measurements for descriptive reporting; an elapsed limit alone does not make a declared complete search incomplete. Compare at least two observed markers on both sides. Report two-point compatibility separately from 2D alignment. A confirmed glyph extent is useful quality evidence; a missing span with a supported centre may still enter the centre matcher. A required comparison with unavailable view, insufficient marker support for its stated claim, or exceeded search limits is **NOT EVALUABLE** rather than a pass.

For each comparison record compatible candidates, distinct physical region count by evaluator label, all admitted correspondence hypotheses, matched marker count, both matched/visible fractions, and the fraction of each visible marker-cloud bounding box spanned by the correspondences when the box area is nonzero. Report 2D support and coincidence with expected registered geometry descriptively. The smaller-side support rule permits a three-point fit to a larger cloud. It measures a local match with incomplete support on the larger side. Candidate scores and margins describe geometry; the best residual cannot make an ambiguous candidate unique.

Report correct unique match, ambiguous region sets, multiple correspondences to one region, false unique match, no-match, and unresolved or unavailable alignment separately. A false unique state requires exactly one fully resolved candidate region and that region must be verified wrong. Group reviewer duplicates by physical region only for evaluation, after matching. Preserve collision counts even on ambiguous trials. Compare the baseline on the same eligible cases and publish its extra abstentions separately. The physical region labels never influence matching scores.

## Bounded diagnostic

The Stage 1 matcher uses exhaustive correspondence enumeration. Implement and test a bounded Stage 2 wrapper before opening holdout answers. Freeze the following deterministic ceilings for this diagnostic:

| Budget | Ceiling |
| --- | ---: |
| Observed markers per view | 24 |
| Reference observations per query | 24 |
| Admissible search prefixes expanded per pair | 100,000 |
| Retained complete correspondence hypotheses per pair | 256 |
| Admissible search prefixes expanded across a query | 600,000 |

Count each entered prefix including the root. Stop with explicit **unresolved · search budget** when work would exceed a ceiling. Record reason, checks, completed references and hypotheses seen. Do not thin a view or prune candidate lists by observed outcomes. A truncated result can never produce a unique or a no-match verdict, even if the partial search found one or zero candidates. Test budget exhaustion on synthetic repeated motifs before touching holdout. Measure warm p50 and p95, candidate counts, attempted prefixes, retained hypotheses and truncations with the actual roster and a fixed synthetic repeated-motif sweep at 1, 2, 4, 8, 16 and 24 reference observations. Use 10 warm-up and 100 timed runs per case on parsed inputs and report calibration and holdout timing separately. This is diagnostic code without a production index.

## Acceptance criteria

Preserve the [Stage 2 representation gate](REPRESENTATION_DECISION.md#2-small-independent-layout-screen-only-if-the-first-stage-passes). Advance to larger representation validation only if the correct region remains compatible in **both fully visible holdout region pairs** and the **changed-player overlap case**, with **zero verified false unique results** in the tested cases. Report both directed reviews for each full pair and each independent directed viewpoint pairing. For a moved-view 2D claim, preserve the Stage 1 requirement for a supported non-collinear triangle. An unavailable required comparison leaves the advance gate unestablished. A verified false unique rejects the rule as a unique identification claim. A genuine ambiguous match stays in the result and its local collision is counted. One held-out layout can falsify a rule on this sample. It cannot establish a population collision rate or target prediction accuracy.

Phase 1.6.3 stops at preparing and verifying the twelve ZIPs. Calibration, code locking for holdout, and representation evaluation follow the return of actual independent annotations. NEXT and WP feasibility remain separately INCONCLUSIVE.
