# Offline benchmark protocol

The prediction unit is one still-hidden target at one observation checkpoint. Score **NEXT to Catacombs Level 3** and **WP on Catacombs Level 2** separately. The fixed scenario is Normal difficulty and arrival from Level 1. Use a synthetic maze family to exercise the same task when verified data for that scenario is unavailable.

## Fixture provenance and isolation

1. Label each run `synthetic`, `classic`, or `D2R`. Record provider revision, input provenance, game build and mode where applicable, area, difficulty, split manifest, and simulation settings. Mixed-source experiments must identify the source on each side explicitly, for example classic references evaluated on D2R observations.
2. Canonicalize complete geometry relative to the entrance, including geometry-equivalent rotations or reflections where the experiment allows these alignments. Group duplicate maps, all observations from a single map, and known variants of the same generation instance before splitting. Keep different hidden target outcomes for a shared geometry in the same group. Do not split observations or hide a few rooms from maps already in the reference pool and count those as held-out evidence.
3. Freeze development/reference, calibration, and evaluation manifests before evaluation. Use development maps for the index and baseline. Use calibration maps for score tolerance and confidence thresholds. Reserve evaluation maps for final reporting. Group multi-source copies when their identities or canonical geometry can be compared. Report the known limits of cross-source deduplication.
4. Start with seeded synthetic runs at 100 and 1,000 reference maps, plus around 200 distinct maps each for calibration and evaluation where the synthetic family supports them. Sweep 10,000 references if enough distinct fixtures are available. Treat smaller D2R samples as pilots. For a D2R decision, target at least 150 independent eligible maps for each target at the primary checkpoint and publish the interval even if it stays wide.
5. Run a separate matcher correctness check with a tiny, deliberately specified candidate universe. Use it to verify true-configuration recovery and missed or false unique fits under ideal, clipped, and noisy observations. Its fixtures stay out of the disjoint benchmark. Track full canonical configuration recovery and exact agreement on observed geometry as different outcomes. Held-out results measure predictions for unseen full layouts.

## Observations

- Generate checkpoints from the stairs arrival and after 1, 2, 3, and 5 observed rooms or exhaustion. Record actual room count and observed feature count. Use a fixed reveal rule at each sampled player position, with a reproducible, target-blind path or teleport sequence. Include partly visible rooms and later recognition of a previously missing connector.
- Run clean observations first. Add seeded trials for clipping, dropped lines and spurious lines or link errors. Give each method the same observation. A missing room, line or edge outside the reveal mask is unknown. Do not pass the reference's true room/template ID or alignment as ordinary input. If an idealized feature or alignment is supplied, label that as a controlled diagnostic.
- Keep target icons, text, labels and anchors in ground truth. Define discovery from the visibility of the labeled target location under the fixture's reveal model. Exclude discovered targets from predictive scoring, and report how many became ineligible at each stage. Use a fixed common eligible cohort as an additional analysis of improvement as more geometry arrives.
- Include symmetric entrances, repeated templates, an out-of-corpus layout, conflicting target positions after an identical prefix, malformed or unrecognizable observations, and an absent target. Add sampled cases as well as hand-authored failure cases. An absent target is inapplicable for accuracy and can be used to check that the method avoids misleading predictions.

## Comparison and metrics

Use a per-target directional baseline derived from development-map target locations conditioned on visible entrance orientation. Start with relative location samples and bin their vectors from the current known player position. When orientation is unknown, use the unconditional development prior. Evaluate this baseline and the geometry matcher on identical eligible observations. If validated procedural rules are available for the same conditions, they can serve as an additional baseline.

| Measure | Definition |
| --- | --- |
| Direction accuracy and coverage | Use four predeclared sectors in grid axes, selected by the dominant signed component of the vector from the player to the target, with a fixed X-axis tie rule. Report top-1 accuracy among predictions, coverage among eligible cases, and correct predictions per eligible case, per target and checkpoint. Compare at matched coverage using the predeclared risk–coverage curves and the same eligible set. Handle tied scores with a fixed reproducible tie policy. |
| Position error | Euclidean distance from predicted anchor to true anchor in canonical units, with median and p90. Also state the nominal room width per corpus. Report coordinate coverage independently of direction coverage. A direction can be useful with no defensible coordinate. |
| Candidate quality and geometry needed | Count distinct compatible configurations and alignments, report median and p90, and count exact, probable, ambiguous and no-match statuses. In the tiny known-universe diagnostic, report true configuration recall and false unique fits. In the disjoint benchmark, report both targets' first usable checkpoint and whether the primary available evidence is at or under three revealed rooms. |
| Improvement after exploration | Show candidate count, coverage, accuracy and position error at each checkpoint. Include paired changes on the fixed eligible cohort and any degradation under noise or different viewpoints. |
| Confidence calibration | Fit any score-to-probability mapping on calibration maps only. Report held-out per-target reliability bins with counts, empirical accuracy and mean assigned probability, plus multiclass Brier score when a normalized sector distribution is emitted. State the denominator and score availability, and pair the table with coverage and no-match rates. Candidate support by itself is a vote share. |
| Latency | Time the complete feature-to-prediction update on changed observations after a documented warm-up. Report p50 and p95 in milliseconds by reference size. Record cold parse/load and index build separately, with the machine, runtime, settings, and repetition count. |
| Memory | Record peak process working set in a fresh benchmark process over load and evaluation and report in MB. Record input size and optional allocation measurements separately. Use a Windows process counter or the process's own peak working-set metric. |

Use the three-room checkpoint as the primary comparison. Freeze thresholds on calibration data and also publish the risk–coverage curves. Report paired 95% bootstrap intervals by resampling independent map groups so multiple reveal steps or repeated noise trials are not treated as additional maps. For a matched-coverage delta, reapply the fixed ranking and tie policy at that coverage in each resample. Keep performance, failure examples and adverse results in the report.
